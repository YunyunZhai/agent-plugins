# gh-search 错误处理参考

本插件的所有脚本都基于 `gh` CLI 调用 GitHub API。以下是常见错误及其处理方式。

## 1. `gh` 未安装 / 未认证

**症状**：
```bash
未找到 `gh` 命令。请先安装 GitHub CLI。
# 或
GitHub CLI 未认证。请运行 `gh auth login` 完成登录。
```

**处理**：
- 未安装 → 引导用户到 https://cli.github.com/ 安装
- 未认证 → 引导运行 `gh auth login`（选择 GitHub.com 账户，HTTPS 协议）
- 认证完成后重新运行脚本

## 2. GraphQL 语法错误

**常见原因**：
- 匿名查询使用了 `$变量` 但未在 `query(...)` 签名中声明
- 使用了 GraphQL search 不支持的限定符（如 `not:fork`，会静默返回 0 结果）

**修复**：
- 使用变量时声明类型：`query($q: String!) { ... }`
- 用 `fork:false` 而非 `not:fork`

## 3. 单仓库无权限 / 不存在

**症状**：某个仓库返回 404 或 FORBIDDEN。

**处理**：脚本会跳过该仓库，继续处理其余仓库，不中断整个流程。

## 4. 网络抖动 / 超时

**症状**：`dial tcp ... i/o timeout` 或 `调用超时`。

**处理**：
- 脚本内置 3 次轻量重试
- 仍失败 → 提示用户稍后重试
- 可调 `GH_SEARCH_TIMEOUT` 环境变量（秒）增大超时

## 5. 结果为空

**症状**：未召回任何仓库。

**可能原因**：
- star 阈值过高
- 语言限定过于严格
- 活跃窗口太小（`pushed:>=<6个月前>`）

**建议**：放宽 star 阈值 / 语言 / 活跃窗口后重试。

## 关键约束回顾

1. 查询侧不能过滤 PR/commit 统计，只能召回后小集合二次查询。
2. description 为空**不丢弃**。
3. commit>X 不作为硬必选，保护稳定低变更成熟库。
4. README 默认关闭，仅深度模式拉取并截断。
